# BeMap MCP

An MCP server that gives AI coding assistants the complete BeNomad BeMap REST
API reference — every service, every request and response field, with types,
enum values and required entitlements.

Developers stop guessing parameter names. The assistant looks them up.

## Why you want it

The BeMap documentation is thorough — 231 pages across the REST, JavaScript and
Flutter APIs — but an assistant helping you write a BeMap request cannot read
it, and the corpus is far too large to paste into a prompt: `RoutingRequest`
alone expands to 45 KB of parameter tables.

This server solves both problems. It ships a snapshot of the whole
documentation and serves it in targeted pieces: a field lookup costs a few
hundred tokens instead of tens of thousands.

The parameter tables are not hand-written. They come from the backend's own
introspection endpoint, so they cannot drift from the running API.

**It works without a BeMap account.** Reading the documentation needs no
credentials and no network — everything is served from the snapshot. Only
executing a real request does.

## Two components

- **The MCP server** — the data: services, parameters, schemas, enforced
  limits.
- **The `benomad-bemap-api` skill** — the judgment: which service to pick for a
  given need, the unit and naming traps that silently produce wrong results,
  and how to read a BeMap error.

They reference each other deliberately: the skill instructs the assistant never
to invent a parameter and to query the server instead. Install both.

## Install

The package is delivered as a tarball, not from the public npm registry:

```bash
mkdir -p ~/bemap-mcp && cd ~/bemap-mcp
npm init -y >/dev/null
npm install /path/to/benomad-bemap-mcp-<version>.tgz
```

Register it with Claude Code:

```bash
claude mcp add -s user bemap -- node "$(pwd)/node_modules/@benomad/bemap-mcp/src/index.js"
```

`-s user` matters: without it the server is registered for the current
directory only and disappears as soon as you open Claude Code elsewhere.

Then install the skill — it is read from `~/.claude/skills/`, never from the
package, so this has to be repeated after every upgrade:

```bash
npx bemap-install-skill
```

Run the same command again after an upgrade — the skill is read from
`~/.claude/skills/` only, so a new version of the package does not update it.

Restart your assistant and ask, in any project:

> What are the required parameters for a BeMap routing request?

Full setup, including Cursor, VS Code, Windsurf and Claude Desktop, plus how to
add credentials for live requests: **[INSTALL.md](INSTALL.md)**.

## What it knows that the documentation does not say

- **Enforced request limits.** Maximum waypoints per routing mode, isochrone
  ceilings, batch sizes — served by the backend at runtime and written down
  nowhere. They differ between environments, and not always in the direction
  you would expect.
- **Required entitlements per service**, so a rejected call is immediately
  readable as a missing role rather than a broken payload.
- **Which release it describes.** Point the server at an environment running
  something else and it says so — and says which side is ahead — instead of
  answering confidently about fields that do not exist there.

## Environments

| Env | Host |
|---|---|
| `beta` | `bemap-beta.benomad.com` |
| `preprod` | `bemap-preprod.benomad.com` |
| `prod` (default) | `bemap.benomad.com` |

Set `BEMAP_ENV`, or pass `env` to `bemap_try_request`. `bemap_limits` always
states which environment its numbers were captured from.

## Requirements

Node.js ≥ 18. No build step. Two dependencies:
`@modelcontextprotocol/sdk` and `zod`.
